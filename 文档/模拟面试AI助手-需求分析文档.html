1. 项目概述

1.1 项目背景

校招求职竞争激烈，应届生普遍缺乏真实面试经验：不知道面试会问什么、回答缺少结构、临场容易紧张，且真人模拟面试（如就业指导老师、学长学姐）资源稀缺、成本高、不可反复练习。

大模型能力已能支撑高拟真度的模拟面试体验，本项目旨在通过 AI 面试官为校招应届生提供低成本、可反复、可量化反馈的模拟面试服务。

1.2 产品定位

面向校招应届生的 AI 模拟面试练习工具，以 AI 实时生成题目 + 动态追问 + 多维度评估反馈为核心能力，帮助用户在秋招/春招前高效备战。

1.3 产品形态

  • 载体：Web 网站（PC 端浏览器访问，便于演示与分享传播，后续可扩展移动端适配）
  • 商业模式：免费 + 会员制（基础面试次数免费，完整次数与不限次会员付费解锁）

2. 目标用户分析

2.1 用户画像

维度描述
核心用户求职季的应届毕业生（大三大四、研二研三）
求职方向不限技术岗——覆盖 17 个方向，非技术岗占 9 个（产品、运营、行政、市场、人力、财务、客服、设计、教育）
核心痛点无面试经验、缺练习对象、回答无反馈、不知道薄弱点在哪
使用场景宿舍/自习室利用碎片或整块时间练习，面试前一晚冲刺

2.2 用户核心诉求

  1. 体验接近真实面试的问答过程（追问、压力感、真实面试官风格）
  2. 面试后被明确告知"答得怎么样、差在哪、怎么改"
  3. 看得见的进步（多次练习的能力成长曲线）

3. 核心业务流程

手机号验证码登录 → 完善求职档案（简历 / 目标岗位 / 考察方向）
        → 选择练习模式 + 面试官人设（+ 专项模式指定练哪一段）
        → 开始面试：AI 出题 ↔ 用户作答（语音或打字），AI 动态追问
        → 聊到建议时长 → 面试官自然收尾，问「还有没有想了解的」
              ├─ 回「没有了」→ 直接结束，出报告
              └─ 还有问题   → 面试官先回答，再接着聊
        → 查看五维评估报告 + 逐题复盘（亮点/不足/改进建议/参考答案）
        → 自动生成学习计划，历史数据沉淀，追踪成长

初稿流程里被删掉的两个环节：

  • 「分享报告」—— 没有实现，相关字段已从数据库删除（见 §4.5）
  • 「制定学习计划」保留，但打卡功能已移除（见 §4.7）

6. 关键风险与结论

初稿列的 6 条风险，逐条给结论：

  1. 语音延迟体验 —— ✅ 风险解除。因为最终没用"云端 ASR → LLM → 云端 TTS"这条链路，而是用浏览器原生 API，语音根本不经过网络，不存在端到端延迟问题。
  2. 浏览器语音能力兼容性 —— ⚠️ 存在。目前 Chrome / Edge 支持好，Firefox / Safari 弱。缓解方式是检测能力并保留纯文字输入。
  3. 支付合规 —— ⚠️ 存在且未解决。当前是模拟支付；真接入需要营业执照（个人开发者拿不到微信/支付宝的网站支付资质）+ 域名 ICP 备案。这是上线的前置条件，不是技术问题。
  4. 出题质量 —— ✅ 已缓解。加了题库兜底（88 道种子题）+ 岗位主线约束 + 四级降级。
  5. 评估一致性 —— ✅ 已缓解但未验证。低温度（0.2）+ 六个固定档位 + 完全确定性的本地规则引擎；但没有做过"模型打分 vs 专家打分"的一致性校验，这是下一步最该补的。
  6. 成本 —— ✅ 可控。做了一处省钱设计：纯拒绝的回答（只说"不知道"且没补充）直接判 0 分，不调用大模型；另有四级降级减少无效调用。
